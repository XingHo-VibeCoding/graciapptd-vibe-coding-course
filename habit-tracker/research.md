# 打卡网站 · 竞品调研报告

- 调研日期：2026-09-18
- 目标用户：自律的人（主动想养成/维持习惯，不需要被"哄"着打卡）
- 调研方法：公开网络资料检索（非付费试用、非爬虫实测），结论以第三方评测与产品官网/商店页为准
- 本文档用途：为"28 天零基础完成的 MVP"划范围，不写代码

## 一、调研对象

从三类动机模型里各选一个代表：

| 产品 | 类型 | 平台 | 为什么选它 |
|------|------|------|-----------|
| Habitica | 游戏化习惯追踪 | Web + iOS + Android | 打卡网站里功能最重的代表，看"上限"长什么样 |
| everyday.app | 极简网页打卡板 | Web 为主 + App | 和我们最像的形态：网页、格子打卡、"别断链" |
| 小日常 | 中文极简打卡 | iOS + Android | 中文市场验证过的极简路线，看"最小可行"长什么样 |

> 另有 Loop Habit Tracker（Android 开源）、Forest（专注种树）作为旁证，不展开。

## 二、逐个分析

### 1. Habitica —— 打卡变成打 RPG

**页面结构（Web 端）**

- 登录后主界面：任务区（Habits / Dailies / To-Dos 三栏切换）+ 右侧角色面板（头像、等级、血量、金币）
- 社交区：队伍（Party）、公会（Guild）、挑战（Challenges）
- 商店/装备：用金币买装饰、装备
- 设置区：任务自定义（难度、频率、提醒）

**主要数据**

- 任务：名称、类型（习惯/每日/待办）、难度、定时
- 打卡记录：完成日期、次数
- 游戏数据：经验值、等级、血量、金币、装备、宠物
- 社交数据：队伍、公会、挑战排名

**用户能完成的动作**

- 增删改任务 → 完成/撤销打卡 → 看角色成长 → 和队友组队互相监督 → 参加公会挑战 → 买装备装扮角色

**优点**

- 游戏化最完整：14 年历史，机制经过长期验证
- 社交激励强：公会/队伍把"坚持"变成社交行为，断卡有真实的同伴压力
- 免费 + 开源，跨平台

**不足**

- 学习曲线陡：新手要先理解 RPG 机制才能打卡，功能太重
- 游戏化反噬：对不玩游戏的人，机制本身成了负担；有评测指出"游戏化会分散对习惯本身的注意力"
- Bug 较多：第三方评测提到连胜（streak）和通知偶发出错
- 技术栈老旧（Node.js + MongoDB，2012 年选型），且据掘金文章称 2026 年 8 月起停止接受社区 PR（此条未经官方核实）

### 2. everyday.app —— 一块颜色越来越深的板子

**页面结构（Web 端）**

- 主界面就是一块板：**每个习惯一行，每一天一列**，打卡后格子填充颜色，连续打卡形成颜色渐变的"链"
- 顶部：习惯排序/颜色/分组设置
- 统计区：当前连胜、历史最长连胜、完成率、总次数
- 无复杂菜单，"打开即打卡"

**主要数据**

- 习惯：名称、颜色、排序、是否"戒断型习惯"
- 打卡记录：某天 完成/跳过/未完成
- 统计：连胜天数、完成率、跳过日

**用户能完成的动作**

- 添加习惯（免费版限 3 个）→ 每天点一下格子 → 跳过一天（不断链）→ 看统计 → 升级解锁无限习惯/颜色/归档

**优点**

- "Don't break the chain"心理模型被视觉化得最好：看到 42 天连续色块，第 43 天留灰会有心理痛感
- 上手零成本：没有游戏机制要学，打开 → 点一下 → 关掉
- Web 优先，浏览器插件可以直接把新标签页变成打卡板
- "跳过不惩罚"设计成熟：生病/度假可跳过，避免一次中断毁掉整个连胜

**不足**

- 只有"是/否"打卡，不支持数量型习惯（如"喝水 8 杯"）
- 免费版限 3 个习惯，无限需付费（约 $29.99/年）
- 统计较浅，适合"看着爽"不适合数据分析型用户
- 无社交、无提醒以外的激励机制

### 3. 小日常 —— 中文极简打卡

**页面结构（App）**

- 今日页：当天习惯列表，图标大、按钮大，点一下打卡
- 打卡完成页：当日习惯全部完成可领一张精美卡片（奖励仪式感）
- 时间线页：打卡记录按日回顾
- 习惯管理页：自定义图标、颜色、时间

**主要数据**

- 习惯：名称、图标、颜色、提醒时间
- 打卡记录：哪天几点打的
- 奖励卡片：领取记录

**用户能完成的动作**

- 创建习惯 → 每天打卡 → 全部完成后领卡片 → 回顾时间线

**优点**

- 极致极简：无社交、无广告、无游戏数值，纯粹打卡
- 界面可爱（中文用户审美友好），学习成本≈0
- "完成日领卡片"用很低成本提供了正反馈仪式感

**不足**

- 功能单一，统计弱（时间线为主，缺少完成率/趋势分析）
- 只有 App 没有 Web，电脑上没法用
- 提醒依赖系统通知，网页形态做不了这个（对我们是重要提醒）

## 三、横向对比总表

| 维度 | Habitica | everyday.app | 小日常 |
|------|----------|--------------|--------|
| 页面结构 | 重：任务+角色+社交+商店 | 轻：一块格子板 | 轻：今日列表+卡片 |
| 核心数据 | 任务+游戏数值+社交 | 习惯+打卡+连胜 | 习惯+打卡+卡片 |
| 打卡动作 | 点击→结算经验金币 | 点击格子变色 | 点击→领卡 |
| 断卡处理 | 角色扣血（惩罚） | 连胜清零（可跳过豁免） | 无明显惩罚 |
| 上手难度 | 高 | 低 | 极低 |
| 平台 | Web+双端 | Web 为主 | 仅 App |
| 最值得抄 | 任务三种类型的设计 | 格子+连胜+跳过 | 极简+完成仪式感 |
| 最不该学 | 重游戏化 | — | — |

**关键洞察（给我们的定位用）**

1. 目标用户是"自律的人"→ 他们不需要游戏化哄着（Habitica 路线否决），需要**快、清楚、不烦人**
2. 三家共同的黄金三角：**习惯列表 + 一键打卡 + 连胜可视化**——这是任何打卡产品的最小内核
3. everyday.app 证明了"纯网页 + 格子板"这个形态单独就能成立
4. "跳过不算断"是被反复验证的成熟设计，第一天就该有，防止用户因一次中断弃用
5. 52% 的习惯类 App 用户 30 天内流失（Global Growth Insights 数据，转引自 tms-outsource.com）→ MVP 别做留存功能，先做"当天打开就能打卡"这一件事

## 四、我的 MVP：28 天零基础可完成的最小版本

### 产品定义（一句话）

> 一个纯网页版的极简打卡板：打开就能看到今天的习惯，点一下打卡，能看到每条习惯的连续天数。

### 三个页面（其实是一页三个区块）

1. **今日打卡**（首页主体）
   - 今天的习惯列表：图标 + 名称 + 连胜天数 + 一个大大的打卡按钮
   - 已完成显示为绿色，点击可撤销（当天内）
2. **习惯管理**
   - 添加习惯：名称 + 颜色（图标可选，默认一个圆点即可）
   - 删除习惯（带确认弹窗，防误删）
3. **记录一览**
   - 每个习惯一行 × 最近 4 周的格子（抄 everyday.app 的核心视觉）
   - 只显示三种状态：完成 / 未完成 / 今天未打卡

### 核心数据（只有两张"表"）

```
习惯 habits：  id、名称、颜色、创建日期
打卡 checkins：习惯 id、日期（哪天打的）
```

> 连胜天数、完成率都不用单独存——**从打卡记录现算**，这是零基础 28 天里最重要的架构简化。

### 用户能做的全部动作（共 6 个）

1. 添加习惯
2. 删除习惯
3. 今日打卡（点一下）
4. 撤销今日打卡（再点一下）
5. 查看某习惯最近 4 周的格子
6. 查看每条习惯的当前连胜天数

### 技术选型（零基础约束下）

| 决策 | 选择 | 理由 |
|------|------|------|
| 存储 | **localStorage（浏览器本地）** | 28 天内不碰后端和数据库；数据在自己浏览器里，天然隐私；`.gitignore` 里已防住任何本地数据文件误传 |
| 形态 | 单文件起步（index.html + style.css + main.js，三个文件封顶） | 零基础能理解全局，改错不用翻十几个文件 |
| 框架 | 第 1-2 周不用框架，纯 HTML/CSS/JS；第 4 周如有余力再说 | 先建立"网页三层"的直觉（Day 1 学过的前端/后端/数据库类比直接用上） |
| 部署 | GitHub 仓库 + 后续用静态托管（如 GitHub Pages） | 仓库流程已经全部跑通，零新增成本 |

### 28 天节奏（按你课程 Day 1-28 的框架）

| 周 | 目标 | 交付 |
|----|------|------|
| 第 1 周 | 已完成：环境、仓库、AGENTS.md、调研（本文档） | research.md 入库 |
| 第 2 周 | 今日打卡页：列表渲染 + 打卡按钮 + localStorage 读写 | 能打卡、刷新不丢 |
| 第 3 周 | 习惯管理：增删 + 确认弹窗 + 连胜计算 + 记录格子 | 三区块全通 |
| 第 4 周 | 打磨：配色、撤销、防重复打卡、部署上线 + 展示 | 可分享的网址 |

### 验收标准（做完什么样算成功）

- 打开网页 ≤ 3 秒内能完成一次打卡
- 刷新/关浏览器再开，打卡记录还在
- 每条习惯能看到当前连续天数
- 手滑误删习惯有确认拦一道
- 今天的格子只允许今天打（不能补昨天的卡——简化规则，见下）

## 五、本期不做（明确写下来，防止做着做着范围爆炸）

| # | 功能 | 为什么不做 |
|---|------|-----------|
| 1 | 用户注册 / 登录 / 多用户 | 一上后端+鉴权，28 天必崩；自己用不需要 |
| 2 | 云同步 / 多设备 | 同上，localStorage 单机够用 |
| 3 | 游戏化（经验、金币、等级、宠物） | 目标用户是自律者，Habitica 的教训：游戏化会分散对习惯本身的注意 |
| 4 | 社交功能（好友、队伍、分享、排行榜） | 需要后端 + 内容审核意识，远超 28 天 |
| 5 | 提醒 / 推送通知 | 网页推送需要 Service Worker + 授权，且电脑端提醒价值低 |
| 6 | 数量型习惯（喝水 8 杯那种计数） | 是/否打卡先跑通，数据模型加一维复杂度翻倍 |
| 7 | 补卡 / 修改历史记录 | MVP 规则定为"只能打今天的卡"，砍掉一整类边界问题 |
| 8 | "跳过不算断"的跳过按钮 | 好设计，但涉及连胜计算逻辑分支，放二期（记入待办） |
| 9 | 数据导出 / 备份 | localStorage 在，导出是锦上添花 |
| 10 | 深度统计（趋势图、热力日历、完成率曲线） | 第 4 周有余力再加最简版，默认不做 |
| 11 | 付费 / 订阅 | 与学习目标无关 |
| 12 | 自定义频率（每周三次那种） | 全部按"每日习惯"处理，规则最简 |
| 13 | 换肤 / 主题 / 深色模式 | 打磨期再说 |
| 14 | 移动端 App / 小程序 | 网页先活下来 |
