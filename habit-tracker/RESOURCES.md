## 三、用量怎么看：每个模块花了多少

**2026-10-15 14:39 实测明细**（只列非零项）：

| 模块 | 资源点 | 占已用比例 | 这个项目里是谁在花 |
|---|---|---|---|
| API calls | **4.59** | 45.9% | 每次前端 `fetch` 打 `/api/*` 都算一次 |
| Cloud function | **3.88** | 38.8% | 云函数运行时长（接口被调用时执行） |
| HTTP gateway | **1.43** | 14.3% | 走公网网关进来的请求 |
| Static website hosting | 0.09 | 0.9% | 前端页面被人打开 |
| Cloud storage | 0.01 | 0.1% | 几乎没用 |
| 其余（数据库 / 认证 / AI / 容器 / 工作流等） | 0 | 0% | 本项目没用上 |

**怎么读这张表**：

1. **前三项占了 99%**，而且**是同一件事的三笔账** —— 有人打开页面、页面调一次接口，
   就会同时记 API calls + 云函数 + 网关。所以"用量涨得快"通常不是出问题，是**有人在访问**。
2. **真正要警惕的是"无人访问还在涨"**。判断方法：连续两个周期对比同一个模块，
   若在没有演示、没有跑脚本的日子里仍稳定增长，先查是不是**有脚本/定时任务在定时打接口**
   （本项目没有定时任务，`drive-user-flow.js`、`core-flow-check.sh` 都是手跑的）。
3. **免费额度的量级感**：3000 点对一个"给人看一眼"的演示站非常宽裕 ——
   本项目从 10-01 建环境到 10-15，含 Day 25~27 反复跑全链路测试，一共只花了 10 点。
   换句话说：**正常用一年也到不了上限**；真到上限，多半是异常刷接口，先查来源再谈扩容。

## 四、导出数据：三步（已实测）

数据库里两样东西**无法从代码重建**：`plan_days`（每日心情）和 `checkins`（打卡/待办记录）。
所以"随时能把数据拿走"这件事必须验证过，不能只写在文档里。

```bash
# 第 1 步：看已有快照（先确认目录在哪、有哪些）
bash habit-tracker/scripts/db-snapshot.sh --list

# 第 2 步：导出一份新快照 → 落到 habit-tracker/db/backups/<时间>.sql
bash habit-tracker/scripts/db-snapshot.sh

# 第 3 步：需要还原时（★ 目标表非空会主键冲突 —— 这是有意的保护，不会静默覆盖）
RESTORE=habit-tracker/db/backups/<时间>.sql bash habit-tracker/scripts/db-snapshot.sh
```

**实测记录（2026-10-15 14:41 真跑）**：

| 项 | 实测值 |
|---|---|
| 产物 | `db/backups/2026-10-15-1441.sql` |
| 大小 / 指纹 | 2699 B / md5 `5e7521098917ab1f9f015ba55135738b` |
| 覆盖 | `plan_days` **7 行** + `checkins` **9 行**，共 2 条 `INSERT` |
| 结果 | 2 通过 / 0 失败，退出码 0 |

**四条必须知道的边界**（都踩过）：

1. **快照含真实数据，所以不入库**：`db/backups/*.sql` 已写进 `.gitignore`（`git check-ignore` 实测命中）。
   仓库是公开的，数据一旦提交就永久留在历史里 —— 别为了"留个备份"把它加进 Git。
2. **产物是"可回放的 INSERT SQL"**，不是二进制备份：能在任何 PostgreSQL 上按行放回去，
   但**不是整库时间点回档**。控制台那种整库回档本项目**没验证过**（免费版能力未知，`RELEASE.md` §5.2 记为 ⚠）。
3. **还原后要重设自增序列**，否则下一条插入会撞已用过的 id：
   `SELECT setval(pg_get_serial_sequence('checkins','id'), (SELECT max(id) FROM checkins));`
   （脚本恢复完会把这条命令打印出来，照抄即可。）
4. **`tcb db backup` 用不了**（MySQL 专用，本项目是 PostgreSQL）；`pg_dump` 也用不了（无直连串、本机无客户端）。
   所以别去试这两条路 —— 那是本项目已经排除掉的选项。

**什么时候一定要导**：发布前 / 要手工改真库数据前 / 到期前要迁走时（见 §五）。

| 情况 | 结果 |
|---|---|
