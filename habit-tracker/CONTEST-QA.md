## 一、给谁用

### 30 秒口头版

> 给**已经在自律、不需要被哄的人**用。
> 调研 Habitica、everyday、小日常之后我发现：这类人真正缺的不是"激励"，而是两件事——**看清今天的时间怎么排**，和**记得今天感觉怎样**。现有产品要么只做清单不做时间轴，要么只有"是/否"打卡、没有情绪，要么用游戏化把自律变成另一种负担。
> 所以这个产品是"一个人的日常记录台"：早上排今天的安排，白天做完点一下，晚上顺手留一句话。**不催、不罚、不哄。**

### 展开

| 维度 | 内容 |
|---|---|
| 核心用户 | 学生/备考、工作 1–3 年的上班族、自由职业者——本来就有自律意愿，讨厌复杂和打断 |
| 典型场景 | 早上 30 秒排今天 → 白天在时间轴上勾 → 晚上写下今天的心情和一句想法 → 周末回看 |
| 他们现在的痛点 | ① 待办是散清单，看不出"今天长什么样"；② 只能记"做了什么"，记不了"感觉怎样"；③ 正经笔记工具（标题/分类/排版）压力太大，写了两次就弃；④ 坚持很久也没人告诉他"你是个什么样的人" |
| 明确不服务 | 团队协作/项目管理（不做多人）、需要强提醒推送的人（不做通知）、想记账的人（记账功能已砍）、要排行榜和社交的人（**刻意不做**） |
| 最强的一条证据 | 我自己是第 1 个用户：连续 28 天真实使用，云端里有真实记录（不是种子数据），最新一条记录就是今晚 22:04 创建的 |

> 加分点：**"不服务谁"说得越清楚，评委会越相信你想清楚了边界。** 别把产品说成"所有人都能用"。

## 二、功能介绍

### 30 秒口头版

> 四个页面，一条主线：**今天做什么 → 想了什么 → 用什么工具 → 我是谁。**
> 「今天」把待办、时间轴、打卡合在一张清单里（这是最近一次改版的主要工作：原来三套视图，用户要来回切）；「思考」是想法流 + 本地 AI 洞察；「应用」是四个小工具（专注计时、纪念倒数日、肯定语、随机话题）；「我的」是情绪周视图和主题换肤。
> 底层是**云端**：4 张表、13 条接口，待办/心情/打卡都同步到云，换设备能读回。全站前后端加起来 818 条自动化断言。

### 展开：按页面拆

**① 今天（默认首页）**
- **一张清单三合一**：时间轴待办、无时间待办、每日打卡混排在一张卡里——有时间的按时间排，没时间的归到「未安排」，打卡显示当天进度（如 `2/2`）。上半年这里是三个筛选标签（全部/时间轴/打卡），实测用户要在三个视图间来回切才看得全，所以整行删掉了。
- **唯一入口「＋ 新建」**：弹一张卡，卡顶分段切「待办 / 打卡」。待办 = 内容 + 时间（可空）+ 四象限（可空）；打卡 = 名称 + **今日次数** + 时间 + 象限 + 起止日期（结束日期不填 = 永久）。
- **保存后不关窗**：一个人一天的待办往往不止一条，保存即清空、卡片留着，连着写；编辑保存才关窗。
- **点整行 = 完成**（不用瞄准小圆圈），再点取消；行内可直接改文字；「···」可删除或移到其他日期。
- **五档心情**：伤心/忧郁/平静/惬意/喜悦，用自己挑的狗狗表情图；选负面情绪只出安抚句，**没有任何"断签""警告"**。
- **自有日历**：顶上一周日历条，可前后翻日期看历史（打勾只能今天）。

**② 思考**
- **想法流**：像发消息一样写，无标题、无分类；长文自动折叠 4 行；每条可编辑/分享/复制/删除。
- **AI 洞察（2 种视角）**：默认洞察（完成率、象限分布、心情）与 MBTI 娱乐版。**全部在本地按规则拼装，数据不出设备**，并明示"仅供自娱，非心理测评"。

**③ 应用（4 个可用 + 1 个占位）**
- **专注计时**：25/15/5 三档 + 自定义 1–180 分钟，开始/暂停/重置，结束响铃并累计当天分钟数。
- **纪念 & 倒数日**：公历/农历双历；置顶大卡「距离 XX 还有 N 天」；支持"每年一次/仅一次"；进入提醒窗口时首页顶部出现提醒条。农历换算是算法内联、离线可用。
- **肯定语**：24 条语录随机 + 点赞 + 5 张背景。
- **随机话题**：随机一个问题，用来破冰/自问（**界面文案目前误写成「随即话题」，已知待修，见第一问的"慎用说法"**）。
- 小组件：锁定未开放（不装作有）。

**④ 我的**
- 头像/名字/使用天数（首次打开自动记录）；本周情绪格（周一到周日，只有今天可改）。
- **主题换肤**：选背景图（内置 6 张或上传）→ **本机 canvas 分析亮度与主色** → 自动切深/浅主题 + 生成强调色，并保证文字对比度 ≥4.5:1；也可手动强制深/浅。全程无网络请求。
- 使用指南压到 3 行（旧版 8 条且已过时），另有「让薯条再教我一遍」重播首访引导。

**⑤ 吉祥物「薯条」**（差异化记忆点）
- 取材自家橘白小奶猫，72px 常驻右下角，**可拖拽**、戳一下会喵；点开是一个本地关键词问答框（14 类），能直接把你带到对应页面。
- 首次访问 3 步引导，替代长指南——**"教操作"交给会随版本更新的引导，"说事实"留在指南**。

**⑥ 数据底座（评委会问的部分）**
- 云函数单入口 `api`，13 条 REST 接口，4 张表（`plan_days` / `checkins` / `habits` / `habit_logs`）。
- 三个关键设计：**写入幂等**（前端 `reqId` / 业务主键 `client_id` / upsert，断网重试不会写两条）；**打卡推整值不是 +1**（重发、乱序、多端同点都不会叠错）；**迁移排在拉取之前**（否则首屏会用"云端没有"把还没上传的本机数据抹掉）。
- 错误分三级：离线 / 服务异常 / 业务规则，前端只有**一个文案出口**，不会出现英文报错。

### 如果有 90 秒现场演示，按这个顺序点

1. 首页点「＋ 新建」→ 写一条 + 选时间 → **保存后卡片还在** → 再写一条（体现"一天不止一条"）。
2. 点整行打勾 → 刷新页面 → **还在**（云端持久化，不是假动画）。
3. 切到「打卡」段，建一个"每天 2 次"的打卡 → 点两下变 2/2。
4. 换一个浏览器/无痕窗口打开同一地址 → **数据还在**（这是 v2.5/v2.6 刚补的短板）。
5. 戳一下薯条 → 它回答并把你带到页面（差异化，评委容易记住）。

## 三、优化方向

按"该先做什么"排序，不按"想做多少"排。

### P0 · 参赛/答辩前必须补的（不做会被当场问穿）

| # | 问题 | 现状 | 打算怎么做 |
|---|---|---|---|
| 1 | **真人试用为 0** | 试用物料（任务卡/记录表/分诊表）已备齐，但只跑过"我自己 + 一个独立盲审代理" | 找 3 个真人各用 5 分钟，只看"第一次能不能自己加上第一条待办"，记录卡点 |
| 2 | **演示/自动化脚本落后于界面** | `scripts/drive-user-flow.js` 还在找已删除的 `#fab`、`#tm-modal`，实测 5 过 4 败；`DEMO-FINAL.md`、`trial/task-card.md` 的操作步骤还是旧界面 | 按当前界面（＋新建弹窗、点整行完成）重写脚本并重跑，文档同步 |
| 3 | **首访有一张风险提醒页** | 用的是腾讯云默认域名，首次访问必现一张"页面访问提示"中间页，需要点「确定访问」 | 唯一合规解法是绑自定义域名（需备案）。答辩时**主动说明**，别等评委点出来 |
| 4 | 错字与过期数字 | 「随即话题」应为「随机」（2 处）；`FINAL-ACCEPT.md` 里"11 张图"实际 6 张 | 随下一个小版本一起清掉 |

### P1 · 产品真实短板（诚实说，别装没有）

1. **没有登录/鉴权**：目前全站共用一个演示身份，任何人拿到链接都能读写同一份数据。这是课程节奏的取舍（一上鉴权 28 天必崩），也是**下一步最该做的第一件事**（匿名登录 → 每设备/每账号独立）。
2. **周报/月报还没做**：PRD 里的 F4（"你是一个___的人"夸夸报告）只有 AI 洞察的雏形，没有按周/月统计。这是产品承诺里最动人的一块，缺它等于少了一个留存理由。
3. **多端并发没有冲突处理**：两端同时改同一条，后写的覆盖先写的。现在的取舍是"打卡推整值天然抗乱序"，但待办编辑仍是最后写入者胜。
4. **单文件已到重构临界点**：`frontend/index.html` 4489 行、无构建无框架。再加两个功能就会难以维护，需要拆成 ES module（不引入框架，保持零构建）。

### P2 · 体验与差异化

5. **PWA 化**（用户最初诉求"想当手机软件用"）：`manifest` + 图标 + Service Worker（**明确不缓存 `/api/*`**），做到可加到主屏、断网能打开。已定方案，未开工。
6. **积分换装**（`pet` 字段已占位）：完成待办 +5、打卡 +3、满圈 +5、连续 7 天 +20；6 件配饰按积分解锁，**只涨不扣**（习惯类产品不宜罚款）。积分从已有数据现算，不新增"事件表"避免两套真相。
7. **吉祥物铺开**：现在只有常驻 + 问答 + 首访，还差"空状态、完成彩蛋、洞察署名"3 个场景（5 个表情已设计）。
8. **数据导出/备份**：换设备目前靠云端，但用户没有"拿走自己数据"的能力。

### 明确不做（写下来是为了防止范围爆炸）

社交/排行榜、付费订阅、小程序重写（等于另一个产品）、复杂推荐算法、多宠物养成。

## 四、我与你（AI）的磨合经验

> 这一问的得分点在**具体**：说"AI 很好用"等于没说。下面每条都有对应的规则文件或踩坑记录。

### 30 秒口头版

> 我最后摸清的一句话是：**把 AI 当成"执行力极强、但没有记性的施工队"。**
> 它不会偷懒，但会**自作主张扩大范围**、会**把"命令跑完"当成"事情做成"**、会**顺着我说"已完成"**。
> 所以我给它配了三样东西：**一次只做一件事的纪律**（写进 `AGENTS.md`）、**能重跑的验收判据**（curl 返回真库数据才算过）、**以及一个会否定我的机制**（关键节点外包独立盲审）。

### 展开：五条具体经验

**1）必须先定"不做什么"，否则 AI 一定帮你多做**
- 教训：早期让它"优化今天页"，它会顺手改配色、改文案、加动画。
- 做法：`AGENTS.md` 写死 **R1 一次一个任务 + 遇边界即停并等确认**；每次任务开头我先写"本次不做"清单。
- 例：合并筛选那一轮，我先用两轮提问把"添加入口放哪、今日次数是什么语义、延长结束日期后怎么算"三个歧义锤死，再让它动代码——省掉了两轮返工。

**2）文档先行，是因为 AI 会"凭感觉"对齐**
- 契约（`api-contract.md`）先改到 v1.9，再写五行代码。不先写契约，AI 前后端会各写一套字段名，最后靠猜。
- 现在项目里 18 份文档 5736 行，PRD 版本号已经到 v3.42——不是爱写文档，是**文档是这个项目的"共同记忆"**。

**3）"跑完了"和"做成了"是两件事**
- 真实案例：环境 ID 记错一个字符，文档/笔记/记忆全是错的；建表脚本写好了却**从没在真库执行过**，`information_schema` 一查是空的——而所有命令都"成功"了。
- 由此定死：**部署完成 = 公网 URL 返回真库数据**（curl + 行数核对），不是命令退出码 0。
- 又一条：`tcb db execute` 返回的 `Affected rows` **不可信**，写完必须 `SELECT` 复核；`fn deploy` 在错误目录跑会"假成功"。

**4）AI 写的检查脚本，也会假绿**
- `check-secrets.sh` 只扫被 git 跟踪的文件 → 新文件不 `git add` 就扫不到，报"零泄露"是假绿。
- `verify-project.sh` 把证据写进仓库内 → 脚本自己造出未跟踪文件，反而把自己的检查项弄红。
- 处理办法是让检查脚本**自证**：拿"必然命中"的样本回灌判据，再加一条"全绿时不许报失败"的反向验证。这套自证抓出的问题比检查本身还多。

**5）AI 会顺着我说，所以必须有人否定我**
- 我自查只能验"我实现了什么"，验不出"用户会不会卡住"。所以关键节点把项目打包交给一个**没参与过开发**的盲审代理，它能挑出"加待办空输入静默失败""顶栏图标点了没反应"这类我自己看不见的问题。
- 视觉上我保留否决权：吉祥物它手绘了 4 版我都否了，最后定的是"照搬我认可的 C 稿 AI 原图、抠透明底"——并且把"严禁手绘重画"写进长期记忆，避免下次又跑偏。

**6）记忆要写下来，不然同一个坑会踩四次**
- "hidden 卡片里的行仍会被 `querySelectorAll` 查到"——这个坑我踩了 4 次，每次都是新的对话、新的 AI。写进 `MEMORY.md` 之后才彻底消掉。
- 现在的做法：每轮收尾固定产出「已 commit + 已 push + 工作区干净 + 改动清单」，踩坑进当日日志，长期规则进 `MEMORY.md`。

## 五、成长进步点

### 30 秒口头版

> 28 天前，我的"完成"是"代码写出来、页面能打开"；现在是**"别人能自己验证它做完了"**。
> 变化最大的是三件事：**会写验收标准**（每条留一个别人能粘贴重跑的证据）、**会做减法**（砍掉记账、砍掉三套筛选、砍掉无关的顶部装饰）、**会判断"这是判据错了还是代码错了"**。

### 展开：可核对的三层进步

**① 认知层：把"完成"的定义换掉**

| | 28 天前 | 现在 |
|---|---|---|
| 什么算做完 | 本地能打开 | 公网 URL 返回真库数据 + 刷新后还在 |
| 遇到"应该没问题" | 直接进下一步 | 先造一条**必然命中**的样本去试，试不出来才敢信 |
| 验收方式 | 自己看一遍 | 逐项表 + 每条一条可重跑的证据 |
| 出错时 | "我真菜" | 先分岔：是**判据**错了，还是**代码**错了 |
| 文档 | 事后补 | 写代码之前先写 |

**② 方法层：从"堆功能"到"做架构判断"**
- `client_id` 做业务主键 → 前后端**零 id 映射**（服务端自增 id 不出响应），这一条省掉了一整层转换 bug。
- 打卡**推整值不是 +1** → 断网重发、乱序、多端同点都不会叠错。
- 迁移**排在拉取之前** → 否则首屏"云端没有"会把你还没上传的历史抹掉（这个 bug 是自查时发现的，先写后删）。
- 同一份数据只留一套真相：积分从 `todos.done` + `habitLogs` 现算，**不新增事件表**。

**③ 工程层：把"我觉得好"变成"可验证"**

| 项 | 现在 | 核对方式 |
|---|---|---|
| 提交 / 发布 | **91 次提交 / 17 个 tag**（v1.0 → v2.6，全部可回滚） | `git log --oneline \| wc -l`、`git tag` |
| 前端 | 单文件 **4489 行**，无框架无构建 | `wc -l frontend/index.html` |
| 云函数 | 3 个文件 **3186 行**（入口/数据层/自测） | `wc -l cloudfunctions/api/*.js` |
| 文档 | **18 份 / 5736 行** | `ls *.md \| wc -l` |
| 自动化断言 | **818 条**（前端 530 通过 / 0 失败 + 云函数 288/288） | `node test-home.js`、`node cloudfunctions/api/selftest.js` |
| 数据 | 4 张表 / 13 条 REST 接口 | `db/schema*.sql`、`api-contract.md` §三 |
| 安全 | 全部 91 个提交**零密钥泄露** | `bash scripts/check-secrets.sh` |

**④ 产品层：学会了做减法**
砍掉记账（无需求）、砍掉三套筛选视图（用户要来回切）、砍掉顶部装饰标题（"没用还丑"）、砍掉"仅限今天"的限制（改成可以改历史）。**能砍掉自己写过的功能，比能加功能更难。**

**⑤ 诚实层（评委会喜欢这个）**
我在 `RETRO.md` 里主动写了一张"我仍然不会的"清单：不会写正经测试框架、不会 React、没有鉴权、不会配自定义域名、后端只有一个云函数。**知道自己不会什么，才知道下一步该学什么。**
