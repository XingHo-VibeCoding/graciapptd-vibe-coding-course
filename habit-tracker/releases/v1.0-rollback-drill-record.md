## 第一次演练：失败及诊断（有价值的部分）

| 项 | 内容 |
|---|---|
| 时间 | 2026-10-14 11:48:41，退出码 **1**，通过 7 / 失败 1 |
| 现象 | 【二】回退验证报 ✗：「线上仍含 v1.0 标识 —— 回退没有生效」 |
| 关键线索 | 【〇】里「上一版指纹」和当前版本**完全一样**：都是 `dc163380…` / 206272 B |
| 原因 | 脚本当时默认 `PREV=HEAD`。Day 26 发布时 HEAD 还停在上一版，所以那天的演练是有效的；**发布提交 `14f36b6` 进了历史之后，HEAD 就等于"已发布的这一版"** —— "回退"部署的是同一份产物，标识自然不会消失 |
| 更危险的地方 | 【二】的指纹比对会打出一个**虚假的 ✓**（两边 md5 本来就相同），整份记录看起来"只错了一项"，实际上**什么都没验证** |
| 修法 | ① 锚点默认值改为**最新版本 tag 的父提交**（`v1.0^`），不再用 `HEAD`；② 【〇】段加**前提守卫**：锚点产物与当前版本指纹相同 → 当场 ✗ 并**不做任何部署**直接退出；③ 结论里的排错指引从 §五（数据恢复）改正为 §六（已知边界与踩坑） |
| 验证 | 改完重跑 → 8 ✓ / 0 ✗（即上方主记录） |
