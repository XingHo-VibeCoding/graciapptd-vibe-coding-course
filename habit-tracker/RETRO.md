## 一、一句话回答

**我把「完成」的定义换掉了：从「我做完了」换成「别人能自己验证它做完了」。**

> ★ 这句是我先替你拟的候选。如果你心里的答案是别的（比如"原来我也能做出上线的东西"、
> "我学会指挥 AI 而不是被 AI 指挥"），**直接替换这一句**，下面四节证据基本都还能用。

改变前后的具体差别：

| | 28 天前（Day 2–7） | 现在（Day 28） |
|---|---|---|
| 什么算做完 | 代码写出来、本地页面能打开 | 公网 URL 返回**真库**数据 + 刷新后还在 |
| 遇到"应该没问题" | 直接进下一步 | 先造一条**必然命中**的样本去试它，试不出来才敢信 |
| 验收方式 | 自己看一遍、觉得看懂了 | 写成逐项表，每条留一条**别人能粘贴重跑**的证据 |
| 出错了 | "我真菜" | 先分岔：是**判断标准**错了，还是**代码**错了 |
| 文档 | 事后补 | 写代码之前先写（R2） |

## 二、这个改变是被四件事逼出来的（都有证据）

### 1. 「部署成功」四个字骗过我一次

Day 17：环境 ID 记错了一个字符（`d3ghf0mjer76ffo02` ❌ → `d9gh0mjel767ff0d2` ✅），
**文档、笔记、记忆里全是错的那个**；更要命的是——建表脚本早就写好了，却**从没在真库里执行过**
（`information_schema` 一查是空的）。

→ 逼出这条规则：**部署的完成标准不是"命令跑完"，而是"公网 URL 返回真库数据"**。
它后来成了 `DEPLOY.md` 的核心，Day 18/19/20 每次部署照文档一遍过。

### 2. 我的检查清单会「虚报通过」—— 而且虚报了整整一天多

Day 25：新写的 `verify-project.sh` 第一轮实跑，就抓出**清单自己的 2 处误报 + 5 处漏报**。
其中一条是真 bug：`check-secrets.sh` 的第 8 条特征会把**纯连字符分隔线**当成"32 位随机串"，
于是从 Day 24 起这道密钥门禁**一直误报为红**，之前"全历史零泄露"的结论都不可信。

→ 由此立下「**判据自证**」：任何检查清单，必须拿**必然命中**的样本回灌给判据。
后来这套自证抓出的东西比检查本身还多。

### 3. 今天我自己又踩了同一个坑（最近的一次证据）

Day 28：刚写的重复执行检测，第一轮三趟实际全绿（22/0、22/0、11/0），
**却报出 3 处 ✗**。根因：`grep -c` 在没有匹配时**会打印 `0` 但退出码是 1**，
我又在后面接了 `|| echo 0`，于是捕获到的字符串成了 `"0\n0"`，跟 `"0"` 比较必然不等。

→ 修完不算完：我给 `repeat-check.sh` 加了「判据自证」组（必然命中样本 + 反向验证"全绿不许报失败"），
**让检查脚本先证明自己没坏，再去检查项目**。

### 4. 「能不能连」不等于「查得到吗」

`/api/health` 是**硬编码返回**的——云端环境变量全坏了，它照样是绿的。
一条只查健康的检查等于没查。

→ 项目验证里必须打一个**真读库**的接口（`/api/day`），才算验过环境变量。
