## 调用 3 · 2026-10-13 · 附加验证：**故意注入**一项缺陷

- **目的**：课程要求"故意弄坏一项，看它能不能查出来"—— 证明这份清单不是摆设
- **做法**：往受跟踪文件 `cloudfunctions/api/db.js` 第 1 行注入一行假密钥（明显是假的，但格式匹配）
- **命令**：`bash habit-tracker/scripts/verify-project.sh --no-net`
- **结果**：**✗ 被准确查获**
  - A 组报「`check-secrets.sh` 报出高危项（退出码 1）」
  - **指名道姓**给出 `habit-tracker/cloudfunctions/api/db.js:1` 那一行
  - 同时命中两条特征（`sk-` 前缀 + 32 位随机串），所以同一行列了两次 —— 属于**双重确认**，不是重复
  - 与此同时，F1「工作区不干净」也如实报了 ✗
- **证据**：`verify-injected.txt`
- **随后**：`git checkout -- habit-tracker/cloudfunctions/api/db.js` **立即撤销**，重跑 `check-secrets.sh` 回到 0 命中、退出码 0 —— 这行假密钥**从未进入 Git 历史**

> **为什么不"留着"这个缺陷**：一旦 commit，它就永久躺在 Git 历史里（这正是【四】段存在的理由 ——
> 删掉提交也改不掉"曾经泄露过"）。所以正确姿势是四步：
> **注入 → 检出留证 → 撤销 → 复绿**，一步都不能少。**演示用的假密钥也不行**，
> 它会污染"全历史 0 命中"这个结论。
