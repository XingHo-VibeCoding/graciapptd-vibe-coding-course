## 1. 项目概述

**一句话**：一个面向自律人群的极简习惯打卡网页——打开就能看到今天的习惯，点一下打卡，能看到每条习惯的连续天数。

**背景**：竞品调研发现三档路线（游戏化 / 网页格子板 / 中文极简 App），目标用户"自律的人"不需要被游戏机制哄着坚持，需要的是快、清楚、不烦人。everyday.app 已验证"纯网页 + 格子板"形态成立。

**产品原则**（做每个决定时回头看的 三条）：

1. 打开网页到完成一次打卡 ≤ 3 秒
2. 不做任何"惩罚"设计（断卡是数据，不是失败）
3. 每个功能先问"自律的人需要吗"，而不是"加这个酷不酷"

---

## 2. 目标用户与场景

**用户画像**：自律者——已经知道自己要养成什么习惯（早起、阅读、运动），打卡是自我记录，不是自我治疗。

**核心使用场景**：

> 晚上学习结束，打开网页，3 秒内点掉今天剩下的 2 个习惯，看到"阅读 · 连续 14 天"，关掉页面。全程不超过 10 秒。

**反场景**（明确不为这些人设计）：需要社交监督才能坚持的人（→ Habitica）、需要游戏奖励的人（→ Forest）、需要深度数据分析的人（→ Habitify）。

## 3. 用户故事（余力加练项，已纳入正文）

**US-01 每日打卡**（核心，对应功能 F1）

> 作为一名**自律的用户**，
> 我想要**打开网页就看到今天的习惯列表，点一下完成打卡**，
> 以便**用最短的时间记录"今天我做到了"**。

验收要点：点击后按钮状态立刻变化（无需刷新）；再点一次可撤销（仅限当天）。

**US-02 看到坚持的痕迹**（对应 F1、F3）

> 作为一名**自律的用户**，
> 我想要**看到每条习惯当前连续了多少天，以及最近 4 周的打卡格子**，
> 以便**用视觉化的"链"给自己正反馈，而不是靠意志力硬撑**。

验收要点：连胜天数从打卡记录实时计算；格子显示 完成/未完成/今天 三种状态。

**US-03 管理我的习惯**（对应 F2）

> 作为一名**自律的用户**，
> 我想要**自己添加和删除习惯，给它选个颜色**，
> 以便**让工具跟着我的生活变化，而不是我被工具绑死**。

验收要点：添加后立刻出现在今日列表；删除有确认弹窗，防手滑。

## 4. 功能需求（本期全部，共 3 组）

### F1 今日打卡（首页主体）—— P0

| 项 | 说明 |
|----|------|
| 内容 | 今天的习惯列表：颜色圆点 + 名称 + 连续天数 + 打卡按钮 |
| 打卡 | 点击→变已完成态（绿色）；再点→撤销。只允许操作**今天** |
| 排序 | 按创建时间；未完成的排前面 |
| 边界 | 当天重复打卡=切换状态；不提供补昨天的卡（MVP 规则） |

### F2 习惯管理 —— P0

| 项 | 说明 |
|----|------|
| 添加 | 名称（必填，≤ 20 字）+ 颜色（预设 8 色选一） |
| 删除 | 需确认弹窗；删除后其历史打卡记录一并清除（并告知用户） |
| 上限 | 最多 12 条（对齐 Streaks 的成熟约束，防目标过载） |

### F3 记录一览 —— P0

| 项 | 说明 |
|----|------|
| 内容 | 每条习惯一行 × 最近 28 天（4 周）的格子 |
| 状态 | 三种：完成（习惯色）/ 未完成（灰）/ 今天（可点击） |
| 语义 | 只读为主，今天的格子与 F1 联动可打卡 |

---

## 5. 数据要求（产品级，不含技术实现）

- 只有两类数据：**习惯**（名称、颜色、创建时间）与**打卡记录**（哪条习惯、哪天）
- 连续天数、完成率**不单独存**，从打卡记录现算
- 打卡记录必须**只属于创建它的用户本人浏览器**，不联网、不上传（隐私底线）
- 数据在关闭浏览器后仍需保留

> 技术上怎么存（localStorage 还是别的）是 Day 5 的事，本 PRD 只约束行为。

---

## 6. 非功能需求

| # | 需求 | 标准 |
|---|------|------|
| 1 | 性能 | 打开到可交互 ≤ 3 秒（普通家用电脑） |
| 2 | 隐私 | 无账号、无网络上传、无第三方统计脚本 |
| 3 | 兼容 | 最新版 Chrome / Edge 可用即可（不承诺手机浏览器） |
| 4 | 容错 | 误删习惯有确认；当天误打卡可撤销 |
| 5 | 可维护 | 代码总量控制在一个新手能通读的规模（三个文件封顶的直觉） |

---

## 7. 验收标准（截图要拍的段落 · 交作业看这里）

**全部满足才算 MVP 完成：**

- [ ] A1 打开网页 ≤ 3 秒内能完成一次打卡
- [ ] A2 打卡后刷新/关浏览器再开，记录还在
- [ ] A3 每条习惯显示当前连续天数，且数字正确（手工连点 3 天可验证）
- [ ] A4 添加习惯：填名称选颜色 → 立刻出现在今日列表
- [ ] A5 删除习惯：出现确认弹窗，确认后才删除
- [ ] A6 今天的格子/按钮只能操作今天，昨天的不可改
- [ ] A7 记录一览显示每条习惯最近 4 周格子，颜色与习惯颜色一致
- [ ] A8 撤销打卡：今天已完成的习惯可再点一次撤销
- [ ] A9 习惯数量达到 12 条后，添加入口提示已达上限
- [ ] A10 部署到可访问的网址（第 4 周完成）

## 8. 本期不做（与 research.md 第 五 节一致）

注册登录 / 云同步多设备 / 游戏化 / 社交 / 提醒推送 / 数量型习惯 / 补卡改历史 / 跳过按钮 / 数据导出 / 深度统计 / 付费 / 自定义频率 / 换肤深色模式 / App 小程序。

> **砍掉逻辑**：每项都问过三个问题——自律的人需要吗？28 天做得完吗？砍掉它产品还成立吗？三者有其一为"否"就砍。游戏化是最大的取舍：调研里 Habitica 的教训明确（游戏机制分散对习惯本身的注意力），且工作量足以吞掉整个 28 天。

## 10. 开放问题（Day 5 技术选型时一并决定）

1. 打卡记录的日期判定用本地时区还是 UTC（跨零点打卡的归属）？
2. localStorage 存储上限约 5MB，按每天 ≤ 12 条记录估算远够用，但是否需要容量提示？
3. 「撤销打卡」是否限制当天 24 点前？（MVP 先按"当天内可撤销"实现）
