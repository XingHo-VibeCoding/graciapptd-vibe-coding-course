## 二、核心流程重复检测（Day 28 板块 ②）

**要回答的问题：同一条核心流程连着跑两遍，会不会留下痕迹？**

```
【自证】判据本身对不对                  ✓ ✓

【二】第 2 遍六环                              22 通过 / 0 失败   ✓
【三】两遍逐环结论逐字相同（22 行）＋通过项数相同        ✓ ✓
【四】零残留；未删总条数回到基线 9 = 9                 ✓ ✓
【五】同幂等键第 2 次 → 409；库内物理行数 = 1；已物理删除  ✓✓✓✓
【六】真浏览器 390px 复跑                      11 通过 / 0 失败   ✓
合计：15 通过 · 0 跳过 · 0 失败
```

**过程中发现并修掉的一个真问题（如实记录）**：
第一轮实跑时，三趟实际全绿（22/0、22/0、11/0），但脚本**误报 3 处 ✗**。
根因是判据写法：`grep -c` 无匹配时打印 `0` 但**退出码为 1**，后面又接了 `|| echo 0`，
捕获到的字符串变成 `"0\n0"`，与 `"0"` 比较必然不等。
修法不只是改这一行——给脚本加了 **「判据自证」** 组（必然命中的样本回灌 + 反向验证
"全绿不许报失败"），**让检查先证明自己没坏，再去检查项目**。
两轮证据都留档：`releases/v1.0-repeat-check-20261015.txt`（含第一轮误报对照）。
