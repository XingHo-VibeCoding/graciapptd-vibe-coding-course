## 三、自测过程里抓出的三个"检查工具自己"的坑（都修了）

1. **等待假通过**：应用是「先渲染本机（新会话=空）→ 云端回来再渲染一次」，
   驱动若以"页面渲染了"为信号，会在**本机空渲染**时就往下走 —— 两次实测
   第 1 步都读到 0 张卡片，其实云端有 6 条。修法：以 `cloud-hint` 以
   「云端数据」开头（= `fetchCloudDay` 成功应用）为唯一放行信号。
2. **reload 后不能拿 `#state-loading` 当信号**：它在初始 HTML 里就带 `hidden`，
   JS 没跑就是 true，等待瞬间假通过 —— 第一次实跑的"刷新后消失"就是这么
   误判的（数据好好在库里 id=43）。
3. **CLI 的 `Affected rows` 不可信**：`tcb db execute` 的 DELETE 报过
   "Affected rows: 0" 但实际删了 2 行，也报过 3 行真删了 3 行 —— **写操作
   之后一律用 SELECT 复核，绝不信 Affected rows**。
