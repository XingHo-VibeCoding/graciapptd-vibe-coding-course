> **这份文件给两个人看，别搞混**：
> - **上半部分（内部说明）** = 给项目主人看的，**转发时不要发**；
> - **下半部分（从「转发起点」那条线往下）** = 整段复制发给试用者，不需要任何项目背景。

> **和 Day 27 那版的关系**：Day 27 的版本是**引导版**——每一步都写清楚点哪里，
> 目的是让真人能顺利走完、拿到"能不能用"的结论。这一版是**观察版**：
> **故意有 2 处不写"怎么点"**，目的是拿到"他第一反应会去点哪里"。
> 两版都保留在同一份文件里没必要，所以直接覆盖，观察版更能出真问题。

## 内部说明（不给试用者看）

| 项 | 内容 |
|---|---|
| 试用链路 | 打开链接 → 看到核心数据 → 一次打卡 → 刷新确认 → 修改 → 删除 |
| 写作原则 | 每步只说"做什么"，**不说原理、不解释为什么**；只给"要做成什么样"，不给"点哪里"（除下面明确列出的两处） |
| **故意含糊 ①** | 第 2 步「打卡」：**不写点哪里**。应用里真正的操作是点待办**左边的圆圈** → 观察他第一反应点的是文字、圆圈、还是长按 |
| **故意含糊 ②** | 第 4 步「修改」：**不写改什么**。应用里"改"只有一种 = 改完成状态；**根本没有"改文字"的编辑功能** → 观察他会不会去找「编辑」、会不会以为功能坏了 |
| 为什么这两处可以含糊 | 都不阻断流程（卡住也有别的路可走），而且都指向本项目**没被验证过的认知差异**——这正是要找的东西 |
| 明确写清楚的三处 | ① 第 0 步腾讯云风险页（不提前说会被当成骗子直接劝退，跟"含糊"是两回事）② 第 5 步删除的位置（误删不好，且"能不能找到删除"不是本次验证点）③ 卡住超过 2 分钟可跳过（避免他直接关掉，数据全丢） |
| **不告知、只观察** | 心情弹窗（当天没选过心情时，进「今天」页会**自动弹**一个选择窗）、两个添加入口（右下角 ＋ 和首页输入行）、刷新后那行"云端数据"小字、空状态文案 —— 一律不写进脚本，全部交给 `record-sheet.md` §三 观察 |
| 配套材料 | 试用者自填 → `feedback-form.md`；主人逐步骤记录 → `record-sheet.md`；拿到记录后怎么选哪条修 → `triage.md` |

### 任务（按顺序做，每做完一步记一笔）

| # | 做什么 | 怎么做 |
|---|---|---|
| 1 | **看** | 进去以后是「今天」这一页。看看今天安排了哪些事，用一句话告诉我你看到了什么 |
| 2 | **打卡** | 把今天的一件事，标记成**已完成** |
| 3 | **刷新** | 刷新这一页（手机往下拉 / 电脑按 F5，或者关掉重新打开链接），确认你刚做的那一下**还在** |
| 4 | **修改** | 改一下你刚才动过的那条 |
| 5 | **删除** | 点这条待办**右边的 ···** → 选「删除」→ 弹出问确认时点「确定」 |

> 哪一步卡住超过 2 分钟，就**跳过它**，接着做下一步 —— 把卡住那一下的样子记下来就行，不用硬扛。

（做完了如果还有 1 分钟：底下那排「今天 / 思考 / 应用 / 我的」随便点一点，看到什么顺手记一句。）

### 边做边记（每题一句话就够）

1. 第 0 步那个提示页：你的第一反应是什么？敢不敢点？
2. 打开工具后第一眼：你知道自己该干什么吗？
3. 六步里，**哪一步卡住了**？卡住的时候屏幕上是什么样？
4. 有没有哪一步**停了很久**（大概几秒）？
5. 有没有哪一步你**不知道点哪**，或者**怕点错**？
6. 随口说说：哪里顺眼、哪里别扭。
