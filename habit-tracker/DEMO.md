## ① 用户问题（40 秒）

**一句话**：我的自律打卡应用原来数据全存在浏览器里——换个设备、清个缓存就全没了。这周要解决的是：**把它搬到云端，让别人打开一个链接就能看到、还能写入真实数据。**

**具体痛点（挑两条讲）**：
- 数据只在本地 → 换电脑/换手机就看不到自己的记录；
- 没有网址 → 想给朋友看，只能把文件发过去，对方还得会打开 HTML。

**本周目标**：数据库 + 后端接口 + 公网部署 + 前端接线，四件事从零打通，最后交付**一个可分享的 URL**。

## ③ 提示词改写过程（60 秒）

**讲法**：这周最大的进步不是学会某条命令，而是**会跟 AI 提要求了**。举两次真实的改写：

**改写一：从「许愿」到「带验收标准」**
- ❌ 早期写法：「帮我实现写入接口，防重复提交」→ AI 按自己想象做，做出来和课程要求对不上；
- ✅ 后来写法：「按 `api-contract.md` 实现契约登记的 POST 接口；防重复按契约约定处理；错误信息用中文写清楚缺了什么；**给出三条测试命令（正常 / 重复 / 缺字段）和数据库 select 验证方法**」→ 把**验收方式**写进提示词，AI 交作业时必须自证；
- 效果：`WEEK3-ACCEPT.md` §一·产出 2 里那 11 条 curl 记录，就是这么来的。

**改写二：从「照单全收」到「要求先质疑」**（本案例核心）
- ❌ 任务清单写「配置跨域」→ 直接让 AI 去配；
- ✅ 实际提示词：「**先做冲突检查，再给方案让我拍板**」→ AI 实测后发现：平台**已经默认配好跨域**，而且免费套餐根本**不允许**手工添加自定义域名，照着做只会白折腾；
- 效果：这一步从「照做」变成了「**验证它确实安全**」，产出是可复核的实测矩阵，而不是一句"配好了"；
- **一句话总结**：提示词从「告诉 AI 做什么」进化成「告诉 AI **做成什么样才算对** + **先质疑前提再动手**」。

## ④ 验证方式（60 秒）

**原则**：每一步都留「任何人当场能重跑」的证据，不信口头汇报。

| 验证什么 | 怎么验 | 预期结果 |
|---|---|---|
| 公网可访问 | 浏览器打开首页 URL / 检查台 URL | 都回 HTTP 200；首页 6 条真库待办 |
| 数据是真的 | 在控制台改一行待办文本 → 刷新页面 | 页面跟着变（看完复原） |
| **可写入 + 持久化** | 页面添加一条 → **刷新** | 提示「已添加到云端」；刷新后仍在，条数 +1 |
| 防重复 | 同一 `clientReqId` POST 两次 | 第二次 `{"code":409,"message":"请勿重复提交…"}` |
| 缺字段有中文提示 | POST 不传 `text` | `{"code":400,"message":"缺少必填字段 text（待办内容）"}` |
| **跨域安全**（本案例） | `curl -i -H "Origin: https://evil.example.com" …/api/health` | 响应里**没有** `access-control-allow-origin`（被拦）；自家域名才会原样回显；三种来源 `*` 通配符出现 **0** 次 |
| 脚本可重复执行 | `schema.sql` 连跑两遍 / `seed.sql` 跑两遍 | 第二遍 0 影响行、行数不变 |
| 重构没改坏 | `node cloudfunctions/api/selftest.js` | **162/162**；契约当日 `git diff` 为空 |

**收尾一句话**：这周交付的不是"一个能跑的网站"，而是「**一张每一项都带证据的验收表**」——`WEEK3-ACCEPT.md` 里 6 项 PASS、0 项 FAIL、2 项如实标未执行。
