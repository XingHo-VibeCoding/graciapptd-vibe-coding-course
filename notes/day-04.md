# Day 4 笔记｜撰写 PRD

## 今天做了什么

- 完成 **PRD.md**（打卡网站 MVP 版，10 个章节）
- 让 AI 按验收标准自检一次：结论无「必须修改」级问题，2 个建议级备注
- 把 research.md + PRD.md 并入课程仓库 `habit-tracker/` 子目录（老师可在一个仓库看全程）

## PRD 核心内容

- 3 条产品原则：3 秒打卡 / 无惩罚设计 / 只问自律者需不需要
- 3 个用户故事（打卡 / 看坚持痕迹 / 管习惯）
- F1-F3 功能：今日打卡、习惯管理（上限 12 条）、28 天记录格子
- **验收标准 A1-A10**（截图拍摄对象）
- 3 个开放问题留给 Day 5 技术选型（时区 / 存储容量 / 撤销截止）

## 今天要掌握的问题：PRD 里砍掉了什么？为什么？

最大一刀是**游戏化**：用户不对（自律者不需要被哄）、时间不对（Habitica 做了 14 年，28 天做半个残次品不如不做）、反面已验证（everyday.app 不做游戏化照样成立）。
次一刀是**登录与多设备同步**：一上后端 28 天必崩；先证明需求存在，再付基础设施成本。

一句话版本：砍掉的游戏化是为了给用户的三秒留路。

## 踩坑/经验

- 仓库转移到组织后名字冲突，GitHub 自动加了 `graciapptd-` 前缀
- 本地 remote 必须跟着改，否则下次 push 直接失败
- 这台机器的内置 Git 有个怪癖：fetch 后远程跟踪引用（refs/remotes/origin/main）写不进去，需要手动写文件修复（不影响实际推拉，只影响 status 显示）
